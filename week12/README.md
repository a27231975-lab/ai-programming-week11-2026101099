# ai-programming-week11 2026101099 배서준

## ① 무엇을 하나요 (What)

성적 CSV 파일을 읽어 유효한 이름·점수 목록과 제외한 행의 기록을 반환하며, pytest로 정상·예외·경계값 동작을 검증하는 프로그램입니다.

### 주요 처리 규칙

- 점수는 0~100 사이의 정수만 허용합니다.
- 열 개수가 두 개가 아니거나, 이름·점수가 비어 있거나, 점수가 정수가 아닌 행은 제외합니다.
- 제외한 행은 줄 번호·원본 행·제외 이유를 기록합니다.
- 빈 줄은 제외 기록 없이 건너뜁니다.
- 따옴표로 감싼 이름 안의 쉼표는 이름의 일부로 처리합니다.
- 같은 이름이 나와도 동명이인일 수 있으므로 둘 다 남깁니다.
- 없는 파일을 읽으면 `FileNotFoundError`가 발생합니다.

## ② 왜 만들었나요 (Why)

성적 CSV에는 빈 점수, 범위 밖 점수, 이름에 포함된 쉼표 등 단순히 읽기만 해서는 제대로 처리하기 어려운 데이터가 섞여 있습니다. 프로그램이 오류 없이 끝나는 것만으로는 올바르게 동작한다고 판단할 수 없으므로, 명세를 기준으로 정상·예외·경계값 테스트를 구성했습니다.

또한 실습에서 구성한 테스트와 AI가 생성한 테스트를 실제 실행 결과와 커버리지로 비교하고, 고장 난 함수에 대한 테스트가 잘못된 반환값을 정답으로 받아들이지 않는지도 확인했습니다.

## ③ 어떻게 쓰나요 (How)

### 실행 환경

실습에서 사용한 환경입니다.

- Windows / PowerShell
- Python 3.14.3
- pytest 9.2.0
- pytest-cov 7.1.0

### 저장소 내려받기 및 설치

Git과 Python이 설치된 환경에서 아래 명령을 실행합니다.

```powershell
git clone https://github.com/a27231975-lab/ai-programming-week11-2026101099.git
cd ai-programming-week11-2026101099

python -m pip install pytest pytest-cov
```

### 프로그램 실행

저장소 폴더에서 실행합니다.

```powershell
python load_scores.py scores.csv
```

다른 CSV 파일을 사용하려면 마지막 파일 이름을 바꿉니다.

```powershell
python load_scores.py empty.csv
```

CSV는 첫 줄을 `name,score` 헤더로 준비합니다.

```csv
name,score
김하나,88
이두리,75
"김, 하나",90
```

### 함수 사용 방법

```python
from load_scores import load_scores

kept, skipped = load_scores("scores.csv")

print(kept)
print(skipped)
```

반환값은 다음과 같습니다.

| 반환값 | 형식 | 의미 |
| --- | --- | --- |
| `kept` | `[(이름, 점수), ...]` | 유효한 학생 데이터 |
| `skipped` | `[(줄 번호, 원본 행, 이유), ...]` | 제외한 행의 기록 |

첫 줄은 헤더로 간주하여 건너뛰므로, 헤더가 있는 CSV를 사용해야 합니다.

## ④ 어떻게 테스트하나요

저장소 폴더에서 아래 명령을 각각 실행합니다.

### 실습에서 구성한 테스트

```powershell
python -m pytest test_load_scores.py -v --cov=load_scores --cov-report=term-missing
```

### AI A 테스트 — 코드 제공

```powershell
python -m pytest test_ai_A.py -v --cov=load_scores --cov-report=term-missing
```

### AI B 테스트 — 재구성한 명세 기준

```powershell
python -m pytest test_ai_B.py -v --cov=load_scores --cov-report=term-missing
```

다음은 원래 실습 폴더에서 확인한 결과입니다. 실행 시간은 환경에 따라 달라질 수 있습니다.

```text

test_ai_A.py:        21 passed in 0.23s
test_ai_B.py:        17 passed in 0.20s
```

| 구분 | 테스트 함수 수 | 실행 케이스 수 | 결과 | 커버리지 |
| --- | ---: | ---: | --- | ---: |
| 실습에서 구성한 테스트 | 10개 | 15개 | 모두 통과 | 80% |
| AI A 테스트 | 10개 | 21개 | 모두 통과 | 80% |
| AI B 테스트 | 8개 | 17개 | 모두 통과 | 80% |

`parametrize`를 사용한 함수는 입력값별로 반복 실행되므로, 함수 개수와 실행 케이스 수가 다릅니다.

### 커버리지 측정과 보완

처음 측정한 커버리지는 76%였고, 실행되지 않은 줄은 `55~56`, `77~86`이었습니다.

- `55~56줄`: 이름이 빈 행을 기록하고 건너뛰는 부분
- `77~86줄`: `load_scores.py`를 직접 실행할 때 결과를 출력하는 부분

이름이 없는 `,88` 행을 입력하는 테스트를 추가했습니다. 유효한 목록이 비어 있고, 제외 기록에 줄 번호·원본 행·이유가 정확히 들어가는지 검사했습니다.

추가 후 커버리지는 80%가 되었고, `55~56줄`은 미실행 목록에서 사라졌습니다.

```text
Name             Stmts   Miss  Cover   Missing
----------------------------------------------
load_scores.py      45      9    80%   77-86
----------------------------------------------
TOTAL               45      9    80%
```

남은 부분은 파일을 직접 실행할 때 동작하는 출력 코드입니다. 현재 테스트는 함수를 불러와 검사하므로 해당 부분은 실행하지 않았습니다.

세 테스트 묶음의 커버리지가 같더라도 기대값, 제외 이유, 원본 파일 보존 등 검증하는 내용까지 동일하다는 뜻은 아닙니다.

### 함정 실험

고장 난 `find_max` 함수가 있는 `bug3_logic.py`를 대상으로 실행합니다.

```powershell
python -m pytest test_ai_bug.py -v
```

실제 결과입니다.

```text
2 failed, 4 passed in 0.18s
```

| 입력 | 올바른 기대값 | 실제 반환값 | 결과 |
| --- | ---: | ---: | --- |
| `[70, 85, 60, 95]` | 95 | 85 | 실패 |
| `[60, 95]` | 95 | 60 | 실패 |

`find_max`가 마지막 원소를 검사하지 않아 두 테스트가 실패했습니다. 잘못된 85를 정답으로 삼지 않고 95를 기대값으로 사용했으므로, 이 테스트는 버그를 굳힌 것이 아니라 검출했습니다.

- ★ 버그를 굳혔나: **X**
- 실험용 원본의 버그는 수정하지 않았습니다.
- 이번 함정 테스트는 `find_max`만 검사하며, `count_pass`는 검사하지 않습니다.
- 빈 목록의 `IndexError` 테스트는 명세가 아니라 현재 구현의 동작을 확인한 항목입니다.

**주의:** 함정 테스트가 포함되어 있으므로 파일을 지정하지 않고 `python -m pytest`를 실행하면 전체 결과에 실패가 포함될 수 있습니다. 정상 기능 비교는 위 명령처럼 테스트 파일을 각각 지정해 실행합니다.

### 직접 수행한 것과 판단한 내용

테스트 파일을 저장하고 PowerShell에서 명령을 실행했으며, 실행 결과를 확인하고 캡처했습니다. 코드 작성과 결과 해석에는 AI의 도움을 받았습니다.

실행 결과를 통해 0점과 100점은 유효하고 101점은 제외됨을 확인했습니다. 빈 이름 테스트 추가 후 커버리지가 76%에서 80%로 상승한 것도 확인했습니다.

함정 실험의 두 실패는 테스트를 통과시키기 위해 기대값을 바꿀 일이 아니라, 원본 함수가 마지막 값을 검사하지 않는 문제를 드러낸 결과로 정리했습니다. AI가 제안한 기대값도 실제 명세와 비교해야 하며, 통과 개수나 커버리지 숫자만으로 정확성을 보장할 수 없다는 점을 확인했습니다.

### 실험 조건의 한계

A·B·함정 테스트는 각각 새 대화창을 사용하지 않고 같은 대화에서 생성했습니다. B 명세도 10주차 작성 원본을 그대로 사용한 것이 아니라 기존 자료와 배포본의 명세를 바탕으로 재구성했습니다.

따라서 이번 결과는 배포 규칙의 ‘각각 새 대화에서 시작’ 및 엄밀한 ‘명세만 제공’ 조건을 완전히 충족한 독립 비교 실험은 아닙니다.

작성 동기와 판단 내용의 문장화에도 AI를 활용했으며, 본 문서는 실제 실행 결과를 바탕으로 정리했습니다.
